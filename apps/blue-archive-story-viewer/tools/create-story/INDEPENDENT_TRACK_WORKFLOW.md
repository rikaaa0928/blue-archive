# 剧情制作工作台：独立产物流程设计

本文档定义剧情制作工作台的新流程。它替代“每一步复制完整剧情 JSON、所有步骤按一条
流水线互相阻塞”的模型。旧 revision 仍作为历史证据保留，新流程不会删除或覆盖它们。

## 1. 目标

视频录制需要两个核心产物：简中字幕与克隆语音。两者在制作期间独立推进、独立修改、
独立判断下游失效；只有最终预览与生成正式录制输入时才组装为完整剧情 JSON。

流程遵循以下原则：

- 导入、繁转简和角色名规范是共享的确定性自动准备；
- 自动可判断的内容不制造人工审核项；
- 人工审核尽早发生，但整体审核代替逐句批准；
- 人工微调入口永久可写，修改以增量记录保存；
- 同一制作版本内不再为每次编辑创建完整剧情版本；
- 只有决定大规模从头重做时才新建 `vNNN` 制作版本；
- 下游通过产物摘要判断是否过期，不通过线性阶段号推断；
- 最终预览发现问题时直接回到对应微调入口。

## 2. 总体流程

```text
批量选择系列片段
        │
自动导入 + 自动准备
        │
 ┌──────┴──────────────┐
 │                     │
简中字幕线            克隆语音线
 │                     │
两次 LLM              ├─ 说话人自动识别
 │                     │    └─ 仅异常项人工确认
整体审查               ├─ 一键准备参考音
 │                     │    └─ 参考音微调
简中微调               │
 │                     ├─ 配音稿 LLM 生成
 │                     │    └─ 整体审查
 │                     │         └─ 配音稿微调
 │                     │
 │                     └─ 生成语音 + 上传 + 试听
 │
 └──────────┬──────────┘
          最终组装与预览
   结构/跳转/默认分支检查
生成正式剧情文件 → 活动索引
          │
默认分支校验 → 视频录制
          │
FFmpeg 完整性验收 → 封面
```

系列批处理只负责选择片段、建立工作区并推进自动准备。片段到达第一个人工节点后即可切换
处理下一片，不等待同系列其他片段。

工作台顶部统一展示所有工作区及系列批处理中的运行任务，包括操作名称、所属剧情、运行时长
和实时日志；当前没有运行任务时，则折叠展示最近任务，避免只能靠终端判断后台现状。

## 3. 共享自动准备

共享准备包含：

1. 检测或同步六张原始表；
2. 确认剧情类型、目录 ID 与 GroupId；
3. 导入多语言原稿与剧情骨架；
4. 繁体转简体、缺失简中补齐与角色名规范化。

输出为不可在微调页面直接修改的 `base-story.json`。上游原始数据或确定性规则变化时，工作台
明确提示重新准备；日常字幕和语音调整不修改这个基础产物。

## 4. 简中字幕线

### 4.1 LLM 生成

默认连续运行两轮中文校对。每轮保存：

- 输入与输出摘要；
- 使用模型、指导意见和运行时间；
- 每行修改前后文本；
- `rationale` 与 `issueTypes`；
- 完整任务日志。

简中校对模型与日语配音稿模型分别配置并持久化，修改其中一个不会影响另一条产物线。

整体审查不逐句批准。页面逐行并列展示日文原文、繁中原文与两轮处理后的简中字幕；LLM 修改
记录中也保留对应的日文、繁中上下文。多次整体生成各自作为独立候选方案保存，审核人可切换
方案并在同一个逐行对照区查看；只有点击“确认采用此方案”后，该候选才成为当前简中产物并
进入人工微调。如果整体不满意，则填写指导意见并重新运行两轮 LLM。旧运行记录只读保留。

已确认方案可以撤销后改选其他候选。撤销确认会把字幕恢复为该候选未经人工微调的内容，并
永久清除当前制作版本中的全部简中人工微调记录；LLM 候选方案及其修改理由不受影响。

### 4.2 永久微调

整体批准后进入简中微调。该入口永不转为只读：

- 可搜索、对照日文/繁中并编辑任意行；
- 一次保存可以包含一行或多行；
- 只记录实际变化的行；
- 每条记录包含修改前、修改后、备注、操作者和时间；
- 不提供覆盖式回滚；采用历史文本时，将其复制为一次新的人工编辑。

简中微调只使最终组装、最终预览、正式 JSON 和录制结果过期，不影响任何语音产物。

## 5. 克隆语音线

克隆语音线有两个并行的前置产物。两者都就绪后才能生成语音，但彼此不互相阻塞。

### 5.1 说话人与参考音产物

角色信息库能稳定匹配的说话人自动确认。仅以下情况进入人工处理：

- 未知说话人；
- 团体发言；
- NPC 或匿名角色；
- 匹配到角色但没有日语语音资源；
- 多候选冲突或自动匹配置信不足。

所有已确认角色通过一个按钮完成资源拉取、参考片段自动选择和远端引用准备，不逐角色审批。

每个待人工确认的说话人显示其所有实际台词位置，并同时给出目标行附近的日文、繁中和简中
上下文。点击任一行号会在同页播放器中直接定位到该句，审核人可继续前后播放确认出场角色；
定位操作复用同一个播放器，不从剧情开头重新加载。

参考音微调是永久可写入口，可试听、替换、增删或上传片段。修改按说话人保存增量记录。说话人
或参考音变化只使受影响说话人的 TTS 与后续语音 URL 过期，不影响简中字幕或配音稿文本。

### 5.2 配音稿产物

LLM 基于日文原文生成带情绪描述的 `TextJpVoice`。生成后进行一次整体审查：

- 生成完成后立即逐行展示日文原文、中文参考与带情绪标签的配音稿；
- 每次生成保存一份完整候选，生成记录可切换，并逐行预览对应方案；
- 生成记录可查看模型、指导意见和逐行修改前后内容；
- 满意时明确确认采用其中一个方案；
- 不满意时填写指导意见并全量重新生成；
- 每次运行保存模型、指导意见和逐行变化记录。

批准后进入永久可写的配音稿微调。人工修改按行保存增量历史。纯标点内容自动标记为无语音，
人工也可随时切换无语音状态。需要改选候选时可撤销确认；撤销会清除基于原候选的人工微调和
手动无语音决定，但不会删除任何 LLM 候选记录，随后可选择并确认另一方案。

配音稿变化只使对应行的 TTS、R2 URL、最终组装和预览过期，不影响简中字幕、说话人确认和
参考音选择。

### 5.3 语音生成、上传与试听

生成输入由当前说话人映射、参考音配置、配音稿与无语音规则共同确定。工作台按输入摘要增量
处理：

- 配音稿某行变化，只重新生成该行；
- ZeroTTS 返回队列已满的 HTTP 429 时，任务提交按 `Retry-After` 或指数退避自动重试；
- R2 仅上传 manifest 标记为新生成或待发布的语音；未变化的行只回填既有 URL；
- 某说话人参考音变化，只重新生成该说话人的相关行；
- 说话人变化，只重新生成受影响行；
- 未变化音频与 R2 对象继续复用；
- 无语音行不创建任务、不播放、不上传，最终 `VoiceJp` 为空。

试听页保留到配音稿微调与参考音微调的直接入口。效果不满意时优先修正输入，不把“相同输入
重新抽取”作为主要制作操作。

## 6. 最终组装与预览

最终组装读取而不改写各支线产物：

- `base-story.json`；
- 当前简中字幕；
- 当前说话人映射；
- 当前配音稿及无语音决定；
- 当前有效的语音 URL；
- 当前录制默认分支。

结构检查、选择页跳转检查和默认录制分支检查放在最终预览。确认这些项目后，工作台直接使用
`assembly/story.json` 和默认分支录制简中 MP4，不提前写入 `public/story`。录制完成必须通过
`ffprobe` 元数据检查和 FFmpeg 完整解码，随后页面使用原生视频播放器提供拖动、暂停和反复
查看。人工明确确认视频通过后，才允许生成正式剧情 JSON；该视频同时作为后续正式录制产物，
不再重复录制。当前版本副本保存在 `production/preview-video.mp4`，页面同时显示录制脚本原始
输出路径，并提供“打开视频”和“在 Finder 中显示”。

默认分支等低概率设置直接修改当前制作版本，不建立完整剧情 revision，但保留轻量操作日志，
并使当前预览视频和确认结果过期。

基础剧情发生增删行或行号漂移时不能静默套用旧增量记录。工作台必须停止组装并提示建立新的
制作版本或执行显式迁移。

发现问题时直接返回简中微调、配音稿微调、参考音微调或说话人修正。修改后只重做摘要已过期
的下游任务，再重新装配和录制预览视频。

## 7. 存储模型

每个制作版本使用以下目录：

```text
versions/vNNN/production/
├── state.json
├── base-story.json
├── tracks/
│   ├── cn/
│   │   ├── current.json
│   │   ├── llm-runs/
│   │   └── edits/
│   └── voice/
│       ├── speakers.json
│       ├── speaker-edits/
│       ├── references.json
│       ├── reference-edits/
│       ├── script.json
│       ├── script-runs/
│       └── script-edits/
├── assembly/
│   ├── story.json
│   └── manifest.json
├── branch-decisions.json
├── branch-edits/
├── preview.json
├── preview-video.mp4
├── event-index.json
└── recording.json
```

`state.json` 只保存当前产物指针、摘要、批准状态和失效状态。历史内容保存在各自的运行或编辑
记录中。任何写入使用临时文件加原子替换。

## 8. 摘要与失效规则

每个产物保存内容摘要。下游保存其实际使用的上游摘要，不维护容易漂移的手工布尔状态。

| 修改 | 失效范围 |
| --- | --- |
| 简中字幕 | 组装、最终预览、正式 JSON、录制 |
| 配音稿某行 | 该行 TTS/R2、组装、最终预览、正式 JSON、录制 |
| 参考音 | 对应说话人的 TTS/R2、组装、最终预览、正式 JSON、录制 |
| 说话人映射 | 受影响行的参考音/TTS/R2、组装、最终预览、正式 JSON、录制 |
| 无语音决定 | 对应行 TTS/R2、组装、最终预览、正式 JSON、录制 |
| 默认分支 | 最终预览、录制 |
| 基础剧情行结构 | 全部支线停止自动套用，要求显式迁移或新版本 |

## 9. 新旧流程边界

新版不导入旧 `review-1/review-2`、完整 story revision 或其批准状态。旧目录不参与新版状态
计算；在新版完成正式剧情文件、语音、录制和验收后，可以按剧情删除。

启用新版时从共享自动准备重新生成 `base-story.json`，并建立全新的字幕、说话人、参考音、
配音稿和最终组装产物。这样可以避免兼容旧线性状态机而污染独立产物模型。角色公共资源缓存等
不包含剧情审核结论的共享下载缓存可以继续复用；剧情级参考音选择、TTS manifest 和 R2 状态
则由新版重新建立。

## 10. 正式文件、录制与收尾

最终预览通过后按以下顺序收尾：

1. 将当前装配原子写入对应的 `public/story`，作为播放器和录制脚本的正式输入；
2. 更新活动剧情索引；
3. 用当前默认分支调用原子配置脚本，并在录制前再次只读校验；
4. 构建播放器、采集剧情并转码简中 MP4；
5. 使用 `ffprobe` 检查媒体信息，并要求 FFmpeg 完整解码成功；
6. 进入独立的“系列封面”页面，让 Gemini 通读所选活动章节的日文原文，先规划整组风格轮换，
   再按顺序生成候选；也可导入已有候选，最后逐章人工选择。

Gemini 系列封面工具会读取各章完整日文剧情，引用本地角色设定图，在脚本内部完成图片生成与视觉复检，
但不会自动选择或发布。创意规则、模型参数、审计产物和人工验收要求见
[`COVER_WORKFLOW.md`](./COVER_WORKFLOW.md)。

录制结果绑定装配摘要与默认分支摘要。字幕、语音 URL 或默认分支变化后，旧视频仍保留为历史
文件，但不再显示为当前有效成品。流程不包含任何视频发布步骤。
